REST e OpenAPI

Recursos no plural, contratos explícitos, Problem Details e OpenAPI 3.1.

GET    /api/v1/solicitacoes
GET    /api/v1/solicitacoes/{id}
POST   /api/v1/solicitacoes
PATCH  /api/v1/solicitacoes/{id}/status
DELETE /api/v1/solicitacoes/{id}
Status

200/201/204 sucesso; 400 request; 401/403 segurança; 404 ausência; 409 conflito de estado; 429 throttling; 500 inesperado; 503 indisponibilidade/readiness.

Contrato

DTO HTTP ≠ entidade de domínio ≠ schema SQL ≠ Entity do Dataverse. Evite vazar implementação para consumidores.

EF Core ou Dapper?

CritérioEF CoreDapper
Produtividade CRUDExcelenteBoa

Abordagem híbrida é permitida, mas “EF para escrita + Dapper para leitura” não é automaticamente CQRS.

Azure e identidade

flowchart LR L[Local] --> DAC[DefaultAzureCredential / login dev] A[Azure Dev/Hml/Prod] --> MI[ManagedIdentityCredential] MI --> KV[Key Vault] MI --> ST[Storage] MI --> SQL[Azure SQL] MI --> SB[Service Bus]

Em Azure, credencial determinística e least privilege. Uma identidade por workload ou boundary operacional relevante; evitar “identidade superadmin” compartilhada.

Dynamics 365 / Dataverse

sequenceDiagram participant W as API / Function / Worker participant E as Entra ID participant D as Dataverse W->>E: token via Managed Identity E-->>W: access token W->>D: ServiceClient/token provider D-->>W: operação autorizada
Atenção: Managed Identity no host não concede acesso automaticamente ao Dataverse. O principal precisa estar corretamente provisionado/mapeado como Application User e receber security role mínima no ambiente.

async Task<string> ObterTokenAsync(string _)
{
    var contexto = new TokenRequestContext([$"{autoridadeDataverse}/.default"]);
    return (await credencial.GetTokenAsync(contexto)).Token;
}

Functions e Workers

Trigger é adaptador, não camada de negócio. Reutilize Application/Domain e implemente integrações em Infrastructure.

flowchart LR TR[Service Bus/Timer/HTTP] --> F[Function] F --> A[Aplicação] A --> P[Port] I[Infraestrutura] --> P I --> DV[Dataverse / SQL / Storage]

Mensageria exige idempotência, DLQ, retry consciente, correlation ID e limites de concorrência.

Configuração e segredos

appsettings.json              -> defaults não sensíveis
appsettings.Development.json  -> defaults locais
User Secrets / .env ignorado  -> segredo local quando necessário
Environment Variables         -> overrides
Azure App Configuration       -> config central
Azure Key Vault               -> segredos/chaves/certificados
Nunca versionar client secret, connection string sensível, token ou certificado privado.

Segurança

  • OAuth/OIDC/Entra ID, audience/issuer/lifetime validados.
  • Authorization policies e least privilege.
  • CORS por allowlist; rate limit quando aplicável.
  • OWASP API Security Top 10 e threat modeling.
  • SAST/SCA/secret scan no CI.
  • Logs sem Authorization header, tokens, client secrets ou PII desnecessária.

Code Review

Classifique: BLOQUEANTE IMPORTANTE SUGESTÃO DÚVIDA

Revise comportamento, arquitetura, autorização, SQL/performance, resiliência, contrato, testes, observabilidade e secrets.

Resiliência e integrações

Timeout explícito, retry apenas para falhas transitórias, backoff + jitter, respeito a Retry-After, idempotência e limites de concorrência. Retry em cascata é um anti-pattern.

Mensageria: ID/correlationId, consumidor idempotente, DLQ monitorada, TTL/MaxDeliveryCount intencionais e Outbox quando banco + publicação exigirem consistência.

CI/CD

flowchart LR C[PR] --> B[Build] B --> S[Analyzers/Security] S --> U[Unit] U --> I[Integration] I --> O[OpenAPI] O --> P[Package] P --> D[Deploy Dev] D --> E[E2E/Smoke] E --> G[Policy/Approval] G --> PRD[Prod] PRD --> V[Health/Telemetry]

Promover o mesmo artefato entre ambientes, obter secrets por identidade/secret store e manter rollback executável.

Validação e erros

Validação ocorre em quatro níveis: contrato, Application, Domain e constraints externas. Falhas HTTP usam Problem Details/RFC 9457; erros internos de SQL/Dataverse não vazam para o consumidor.

Upgrade de APIs legadas

flowchart LR INV[Inventário] --> CAR[Testes de caracterização] CAR --> SEC[Segurança/deps] SEC --> NET[.NET 10] NET --> CFG[Config/identidade] CFG --> OBS[Observabilidade] OBS --> ARC[Refatoração incremental] ARC --> ROL[Rollout]
Sem big-bang. Preserve contrato, crie testes antes de refatorar comportamento e migre boundaries por fatias.
